# AGENTS.md

## 项目是什么

一个多人共享记账的 Web 应用。用户建群、记账、系统算出谁欠谁多少钱，
并给出转账笔数最少的结算方案。

完整需求在 `docs/PRD.md`。功能需求都有编号（FR-xxx），
每次任务只实现明确指定的编号，不要顺手多做。

## 这个项目只在本地跑

不部署、不上线、没有真实用户。所有设计决策优先考虑「能不能演示」，
不考虑并发、扩展性、安全性、多语言。

具体意味着：

- 没有注册登录。用一个假的用户切换器代替，见下方。
- 数据库是本地 SQLite 文件，随时可以删掉重新 seed。
- 不写鉴权中间件，不校验权限，不做 rate limit。
- 不需要 loading 骨架屏之外的性能优化。

## 技术栈

- Next.js App Router + TypeScript（严格模式）
- Prisma + SQLite（`prisma/dev.db`）
- Tailwind CSS
- Vitest 做单元测试

## 常用命令

```bash
npm run dev              # 本地开发
npx prisma migrate dev   # 生成并应用迁移
npx prisma db seed       # 重新灌入演示数据
npx prisma studio        # 查看数据库
npx vitest run           # 跑测试
```

## 假登录

不做真实认证。当前用户存在一个 React Context 里，
页面右上角有一个下拉框可以切换成群组内的任意成员。
切换后整个页面按新身份重新渲染（谁欠谁、我该付多少）。

服务端需要「当前用户」时，从请求里读一个 `x-demo-user-id` 头，
不要写任何 session 或 token 逻辑。

## 演示数据

`prisma/seed.ts` 必须能一条命令灌出一个可以直接演示的状态：

- 5 个用户，其中 1 个是没有账号的虚拟成员
- 2 个群组：一个「合租」（长期、账单多），一个「夏威夷旅行」（短期、接近结清）
- 每个群组 10 到 15 笔账单，覆盖均分、按比例、按金额三种分摊
- 净额刻意构造成能体现最优结算价值的形态：
  简化前需要 5 笔转账，简化后只要 3 笔

空数据库演示不出任何东西。seed 的质量直接决定 demo 的质量。

## 金额处理（最重要的规则）

- 所有金额一律用「分」为单位的整数存储和计算，字段名统一以 `Cents` 结尾。
- 任何地方都不允许用 float 或 decimal 表示金额。
- 分摊产生的余数用最大余数法分配，必须保证 `sum(shares) === total` 恒成立。
- 只在渲染到界面的那一刻才除以 100，其他任何地方都不做这个转换。

## AI 解析

收据识别（FR-3xx）和自然语言记账（FR-4xx）是同一个模块，
统一放在 `src/lib/parse-expense.ts`：

```
parseExpense(input: { type: 'image', data: string } | { type: 'text', data: string },
             members: Member[]) => ParsedExpense
```

两种输入走同一个模型调用、返回同一个 JSON schema、接同一个确认表单。
不要写成两套。

必须支持 mock 模式：环境变量 `MOCK_AI=true` 时，
直接返回 `src/lib/__fixtures__/` 里的预置结果，不发任何网络请求。
录屏演示时会开启这个模式。

解析失败、超时、字段缺失时一律降级到手动录入，绝对不能白屏或报错弹窗。

## 代码约定

- 业务逻辑放 `src/lib/`，必须是纯函数、不依赖数据库、可以直接单元测试。
- 数据库读写放 `src/server/`，React 组件里不直接调 Prisma。
- 组件放 `src/components/`，页面放 `src/app/`。
- 用具名导出，不用 default export（除了 Next.js 的页面文件）。
- 不要写注释解释代码在做什么，只在逻辑不直观时解释为什么这么做。

## 边界

- 不要修改 `docs/` 里的任何文件。
- 不要安装新的生产依赖，先问我。
- 不要碰 `prisma/migrations/` 里已经存在的迁移文件，只新增。
- 不要为了让测试通过而修改测试的断言。测试挂了就修代码。
- 不要添加任何跟部署有关的配置（Dockerfile、CI、Vercel 配置等）。

2. `npm run dev` 能启动，相关页面能打开且不报错
3. 用一句话说明你改了哪些文件、为什么
4. 列出你做了但 PRD 里没写死的假设

如果有任何地方 PRD 没说清楚，停下来问我，不要自己猜一个实现了事。
